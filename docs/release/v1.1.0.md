# query-lang v1.1.0

A fix for queries that recover from a cycle, a fix for panics inside `compute`, and an optional depth limit.

## Fixed

- **Recovered cycles no longer overflow the stack.** A query may catch the `Cycle` error from a dependency and fall back to a default. That left two cached queries that depended on each other, and after the next `set`, revalidating either one recursed until the stack overflowed. A query is now marked as in progress while its dependencies are revalidated, and a dependency that now fails makes the query run `compute` again. The values match what a fresh database computes.
- **A panic in `compute` no longer leaves a false cycle behind.** If the caller caught the panic, every later `get` of that query used to report `Cycle`. The internal bookkeeping is now unwound on panic too.

## Added

- `Database::with_max_depth(depth)` and `Database::max_depth()`. Resolution uses native stack for each level of a dependency chain, so a very long chain can overflow the thread's stack. With a limit set, a `get` that would go deeper returns `QueryError::TooDeep`, and the database stays usable. There is no limit by default.
- `QueryError::TooDeep`. The enum was already `#[non_exhaustive]`, so this is an additive change.

## Upgrading

No code changes are needed. A `match` on `QueryError` already needs a wildcard arm, and it now also covers `TooDeep`, which only appears when you set a depth limit.

MSRV is unchanged at Rust 1.85.
